# 本机验证范围

## v1.1.6（2026-10-16）

- 13 个验证工具使用生产 manifest 与优化选项编译通过。128 项 `TrayPointerCheck`、172 项 `SwitcherSelectionCheck`、26 项 `DesktopStartupCheck` 通过。并回归 52 项响应、26 项壁纸、172 项开始菜单、29 项像素/延迟、键盘监听及两个副屏原生菜单检查。
- 指针检查覆盖远控原地注入回声与真实一像素移动的区别、真实点击/滚轮撤销、归还失败/抛错/读位置暂不可用时的有界重试、待归还时拒绝重入、恢复后禁止迟发点击，以及关闭并卸载监听后不再发生延迟归还。采用模拟输入后端，不等于在朋友电脑复现了偶发故障。
- 窗口选择检查使用五个同标题真实 HWND，覆盖不同列宽的首行末卡、真实 DWM 源尺寸、按下后重排取消、标题变化保留身份、鼠标请求与 Alt 松开竞争，以及 Esc/新手势取消旧请求。通过独立图形按钮获得正常前台权限后，另有 8 项实际 `Native.Activate` / `GetForegroundWindow` 检查通过：两个副屏均从前台 B 切到对应卡片 A。卡片和 Alt 回调由夹具调用；本轮未宣称完整物理 Alt 长按验收。
- 桌面位置读取改为后台单执行、仅保留最新待处理请求。阻塞假 Explorer 读取时，界面计时器继续运行；关闭、旧代次、屏幕移除及几何变化后的结果被丢弃。目录枚举、图标布局仍保留在界面线程，不承诺全部冷启动工作异步或零等待。
- 最终源码的私有启动检查在构造完成后立即收起设置，约启动后 779 ms 首次查询 `Shell_NotifyIconGetRect` 返回成功，随后 2.5 秒内保持已登记。没有把 `NotifyIcon.Visible` 当作 Shell 成功依据。图标可能位于 Windows 隐藏图标菜单，本程序不替用户更改固定设置。
- Computer Use 通过正常预览窗口，调用正式托盘捕获/转发/指针代码，实际音量和网络均在副屏打开 Windows 快速设置；点击前后鼠标分别保持副屏 `{2987,888}` 与 `{2934,888}`。高响应开启。该检查是预览入口，不等于所有原位图标与跨机器长时间压力验收。
- 实测确认：手动隐藏已搬动的原生菜单，主屏截图可能继续显示展开箭头。仅缓存收起截图不能覆盖所有状态，已撤下该额外缓存方案。识别到真实隐藏图标菜单后，副屏使用助手自己的展开/收起箭头状态；使用既有 `TrayNotifyWnd` 首个 32 逻辑像素按钮区域，按源 DPI 缩放，其他图标继续更新。实际展开后点击旁边，预览中的箭头恢复朝上；绘制回归覆盖 100/150/200% 源缩放、透明点击通道和邻图标像素不变。第三方改变按钮结构的布局尚未验收。
- 一次在真实系统弹窗仍打开时运行开始菜单检查，系统栏自然显隐导致“任务栏几何未变”断言失败；保留记录后退出交互测试，在桌面稳定时原断言 172 项通过，没有删除断言。
- 本轮没有引入第三方运行库。Windows 10、朋友的 TranslucentTB 环境、不同远控软件及长期偶发问题仍需设备反馈；测试日志、个人配置和桌面截图不公开。

## v1.1.5（2026-10-14 至 15）

- 11 个验证工具使用生产 PerMonitorV2 manifest 和优化选项编译通过。172 项 `StartMenuCheck`、84 项 `TrayPointerCheck`、29 项 `LatencyCheck`、52 项 `ResponseCheck`、26 项 `WallpaperCheck` 及两个副屏的 `TrayPopupCheck` 通过。托盘新增隐藏启动、幂等初始化、内容桥显隐及从未显示就关闭时的资源释放检查。
- 开始菜单检查涵盖实际 DWM 句柄、原生焦点保留、混合分辨率、隐藏/cloak 后位置还原、异步监听就绪和释放。鼠标配对检查涵盖拖动、快照过期、隐藏/关闭取消、标记输入绕过及独立消息泵；使用自身窗口和模拟轻量关闭顺序，没有向真实 Start 注入鼠标输入。
- Computer Use 以真实 Ctrl＋Esc 打开 Windows 开始菜单，确认主屏原生画面与副屏透明 DWM 镜像同时显示。正常退出候选前后，原生 Start 均在主屏 `{0,0,1920,1032}`，无需再次手动恢复。
- 真实音量和网络通过正式转发代码在副屏打开快速设置；点击前后鼠标分别保持副屏 `{3011,889}` 和 `{2932,889}`。这是正常窗口预览的转发实测，不等于所有原位托盘图标已经验收。
- 自动化实点镜像“全部应用”受到测试工具的前置激活影响。被动事件记录确认：镜像先收到前台事件，原生 Start 的 `cloak=2` 发生在鼠标 down 前约 62 ms，程序正确取消过期点击。只读核对原生按钮的实际输入根与 DWM 源一致；未通过争抢焦点或强制重开菜单规避工具限制。随后用户在完整候选版上通过远控手动按 Win，并在副屏真实点击“全部”，确认应用列表正常展开且 Win 能收起；这是人工交互验收，区别于受控夹具和工具点击。
- 当前实际 Shell 自动隐藏时 HWND 仍可见、未 cloak，但屏幕交集仅 2 像素，XAML 内容桥也隐藏；曝光判断会返回隐藏。若已识别的内容桥全部隐藏，即使外框矩形完整也不显示复制托盘；旧 Shell 无该桥时沿用几何判据。自身原生子窗口验证单桥、多桥、隐藏、裁剪及无桥兼容路径。
- 完整候选的实际 Shell 只读记录确认自然展开时原生栏为 `{1920,1032,1920,48}`、复制托盘可见，随后原生栏收至 `{1920,1078,1920,48}`、复制托盘隐藏。用户调整远控模式后也确认底边能呼出任务栏；先前“平时无法呼出”不作为程序遮挡证据。五处底边命中均为真实 Shell，与程序退出时相同。
- Win 镜像避开真实任务栏及自动隐藏触发边缘；不强制移动或展开任务栏，不改自动隐藏配置。仅移动任务栏外框不能证明 Shell 内容已展开，该试验已撤除。副屏任务栏继续由 Windows 的原生悬停行为展开。
- 透明像素完整输出与 v1.1.4 的六组基线逐字节相同。780×72 带色壁纸本机处理中位数约从 51 ms 降至 14–16 ms；不同负载存在波动，只测背景分离，不包括截图、输入和系统动画。缓存仍受限，未承诺总内存或零延迟。
- Windows 10、朋友的 TranslucentTB 电脑、搜索/滚动/独立菜单仍未完整验收。诊断日志、个人设置和截图不随源码或便携包公开。

## v1.1.4 透明任务栏兼容（2026-10-12）

- `WallpaperCheck` 26 项通过。180×48 的复杂壁纸夹具中，旧算法在 8064 个背景像素内分别留下 7864 / 7856 个非透明像素，新算法在清晰及带色透明背景中均为 0；白色、黑色和彩色图标保留。此为合成夹具，不等同于朋友电脑的 TranslucentTB 实测。
- 不透明任务栏和不相关背景拒绝壁纸参考，输出与原有分离算法逐像素一致；验证适应、填充、居中、拉伸、负坐标平铺、跨屏裁剪及适应模式的背景颜色。跨屏项仅验证裁剪尺寸。
- 通过 Windows `IDesktopWallpaper` 实际读取本机三个显示器各自的壁纸裁剪；超过 1 MiB 的裁剪请求被拒绝。旧配置默认启用兼容且保留原响应档位，关闭开关保存/重载通过。
- 通过托盘实际 `RefreshHiddenClock` / `SetImage` 路径检查：自动隐藏后的透明帧保持壁纸匹配和真实图标，未重画主屏时钟污染背景参考。
- 八个验证工具编译通过；52 项 `ResponseCheck` 通过（新增设置行在 14 号字体下无重叠）。两个副屏原生 `TrayPopupCheck` 回归通过，准确 HWND、菜单边界、关闭后不重开及普通窗口保护保持。
- Computer Use 实际操作桌面 v1.1.4 设置页：旧配置加载时兼容默认勾选，取消并应用后配置保存为 0，再勾选应用后保存为 1。高响应仍为 0，目标屏、清晰度及其他原选项保持；截图核对整页文字与按钮无重叠。
- 本机没有运行 TranslucentTB；未声称朋友电脑、动态壁纸、HDR、应用背景覆盖或所有任务栏美化软件全部验收。任务栏自动隐藏时测试的 `PrintWindow` 返回黑图，DWM 路径未取得有效真实托盘画面，因此没有采用这些实验方案。

## v1.1.3 高响应模式（2026-10-12）

- `ResponseCheck` 51 项通过：旧配置默认普通模式、开关保存/重载、普通模式不保留额外图片、LRU 淘汰/上限/复制隔离/释放、实际桌面图片后台到达、刷新时缓存立即可用、修改文件或清晰度后缓存失效、14 号字体行间无重叠、真实 DWM 预览句柄在重复布局中复用、关闭自身测试窗口及鼠标消息线程在主线程阻塞 400 ms 时仍响应。
- 合成 520×48 托盘图像的透明输出逐像素比较一致，白色/黑色图标和透明背景保留。连续 60 帧平均约 8.1 ms/帧、Gen0 回收次数为 0，保留像素缓冲 199680 字节（约 0.19 MiB）。这是本机单一合成图像测量，不能当作其他机器的实际托盘点击延迟。
- 七个验证工具编译通过；`KeyboardCheck` 与 `TrayPopupCheck` 回归通过，两个副屏原生菜单准确定位、关闭后不重开，普通窗口未被误移动。
- 用 Computer Use 在桌面正式 v1.1.3 设置页实际勾选并应用高响应模式，读取便携配置确认保存为 1；Ctrl＋Esc 打开真实开始菜单后，原生 Start 画布处于目标副屏 X=1920、1920×1032，切回设置后 DWM 确认菜单已隐藏。关闭开关并应用后保存为 0。正式设置页截图核对控件清晰无重叠。
- 高响应模式只缩短程序内部等待；真实任务栏展开的稳定命中等待以及键盘移屏的原生选择完成等待保留。缓存受上限控制，未通过无用分配来增加内存；总进程内存和 CPU 未承诺固定值。
- 本轮用户反馈物理 Win 键已有反应，但偶有迟缓；这是用户的 v1.1.2 实测反馈，不能作为 v1.1.3 的完整功能验收。其他设备和 Windows 10 未重新验收。

- `KeyboardCheck` 通过左右 Win、重复按下、孤立松开、Win＋E/D/S/R/方向键及预先按住的 Ctrl/Alt/Shift 排除；五次输入线程创建/关闭及主线程阻塞 400 ms 时的真实消息循环探测通过（本机响应 0 至 2 ms）。这些是事件逻辑和线程检查，不是物理 Win 键实测。
- Computer Use 工具禁止自动注入 Win 键，用户本轮无法配合物理按键，因此实际菜单路径用 Ctrl＋Esc 验证。未声称物理 Win 键、Win＋E 完整桌面交互或其他电脑全部验收。
- 六个验证工具编译通过；重新执行 `TrayPopupCheck`，两个副屏的原生菜单位置、关闭及普通窗口保护通过。本轮未完整重跑其他四项。
- 独立键盘线程依据 [Microsoft LowLevelKeyboardProc 文档](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc) 避免界面繁忙导致全局监听超时。

## v1.1.0

v1.1.0 的实际交互回归于 2026-10-09 在 Windows 三屏环境完成；主屏 100% 缩放，右侧目标副屏 1920×1080、150% 缩放，另有负坐标左侧屏幕。

通过的检查：

- 真实 Alt+Tab 显示副屏面板，同时保留主屏原生切换器。
- 两个同名测试窗口分别绑定 HWND、DWM 预览、点击和正常关闭；只关闭指定窗口。
- 无标题窗口、所属对话框、隐藏宿主对话框识别及实际预览与点击。
- 鼠标选中和松开 Alt 后移动原生实际选中的窗口；关闭选项时只切换；Esc 取消时不移动。
- 普通、最大化、最小化窗口及负坐标副屏移动；最大化状态保留。
- 三档实际图片缩略图、边长限制、宽高比例和后台缓存刷新。
- 透明背景通道、深浅色图标保留；实际截图核对副屏原生时钟没有镜像时钟叠加。
- 控制面板不同缩放和较大字体下行间无重叠，应用按钮保存便携配置。
- 托盘物理像素对齐、展开及自动隐藏；完整原生菜单、真实图标右键、Esc、再次点击和外部点击收起。
- 界面阻塞 1.3 秒期间仍收到外部点击，恢复后收起托盘菜单。

最后一次完整回归中托盘菜单展开为 125 毫秒，不是其他电脑的性能保证。

发布准备于 2026-10-10 核对源码、版本和便携包。干净目录构建检查与上述图形交互回归属于不同验证范围。

这些是本机证据，不能代替其他设备验收。全屏游戏抓取输入时，应先切回桌面再做交互验证。测试生成的截图、日志、配置和桌面文件名不随仓库公开。
